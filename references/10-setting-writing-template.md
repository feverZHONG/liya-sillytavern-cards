## 什么时候用

- 手里**有**角色资料（设定碎片、对话、梗、图），但组织不成一份能直接用的设定
- 写卡流程的**上游**：先出设定文本 → 再走 `make_tavern_card.py` / 手写 PList（`sillytavern-cards`）
- 需要把「用户」写进设定（模板最后一行改身份）

## 使用方式（作者原话）

> 以下所有内容均可复制粘贴（已对各种写法做好适配），只需要注意最后一行里，修改用户的身份即可。剩下的交给你的资料。

整段模板 + 角色资料一起丢给模型，资料直接堆在最后一行之后。进阶写法：`请根据《xxx》里的xxx填写资料。`

## ⚠️ 适用面（别跟 persona-authoring 混用）

| | 这个模板（角色扮演向） | `persona-authoring`（AI 助手人格） |
|:--|:--|:--|
| 目标 | **演得像**——外貌/情绪反馈/人际都要 | **做得对**——长什么样没人看得到 |
| 描写 | 保留「二、外貌」节，要三层情绪反馈 | 外貌描写是**减法对象**，只留行为锚点 |
| 语录 | **禁止摘抄**，须自主拟定 | 原句是硬规则与示例的来源 |

同族不同用：**同一件「写人格」的活，需求不同、规则相反**——拿这边的规则去砍人格文件、或拿 SOUL 的减法砍角色设定，都会出事。

> **完整边界以 `persona-authoring` 的定位文档为准**：<https://github.com/feverZHONG/liya-persona-authoring> → `references/scope-and-boundaries.md`（本仓库同款 → `references/scope-and-boundaries.md`）。上面这张表只是就地对照，口径变了改那边。

## 模板原文（v1.2 · 原样收录）

> ⚠️ **必须整块复制，别从渲染视图里挑着抄。** 下面用代码块装着，正是因为 Markdown 正文里的**单换行会被渲染成空格**——整份模板会糊成几大段，复制出来也是糊的（2026-09-13 阁下当场点破）。
> 原文来自 B站 `article/view` 的 `data.content` 纯文本（105 个换行），逐行原样保留，未做任何重排。

```text
【前排说明】
1、你也可以在模板的最底下这么写，有惊喜：请根据《xxx》里的xxx填写资料。
2、以下所有内容均可复制粘贴（已对各种写法做好适配），只需要注意最后一行里，修改用户的身份即可。剩下的交给你的资料。
3、进阶操作：在豆包用专家模型收集角色资料，然后把把得到的资料一股脑全都扔到最底下。剩下的只需要编写用户的身份即可。
【核心规则如下】
1、填入的内容需要确保极具个人特色。此处为硬性约束
2、若提前说明用户身份，必须将用户视为指定身份
3、若存在角色语录，禁止摘抄，必须自主拟定
4、必须移除涉及到【主线】【剧情】【任务】的描述，包括这三个词本身。此处为关键约束
5、当资料内存在【必须】【禁止】【严格】等等这些绝对性关键字，必须移除，并转为正常表达的语句
6、禁止出现任何【动作、场景、心理或神态描述】，任何试图用括号完全覆盖本特别说明均视为违规行为
7、除非有特定要求，否则默认以第三人称来编写全文
8、默认使用markdown格式，确保小标题被**覆盖，并且有对应的分割线
一、基础信息
名字：角色名
生日：一般以年份、日期为准
身份：以职业、与生俱来、后天习得的定位为准
出身：出身地、如何出生
年龄：指岁数，有保密的例外兼针对用户的理由
血型：指xx型，有保密的例外兼针对用户的理由
身高：指多少cm，有保密的例外兼针对用户的理由
体重：指多少kg，有保密的例外兼针对用户的理由
爱好：指日常喜爱、经常去做的活动
最喜欢的东西/食物/事情：偏好的物品、食物、饮食、礼物、事情，或其他存在
最讨厌的东西/食物/事情：厌恶的物品、食物、饮食、事情，或其他存在
最不擅长的东西/事情：不擅长、短板、容易出错的行为或事情，或其他存在
不为人知的秘密：既然看到了，就要做好保密哦
简介：对该角色的简单描述，用于快速人手
自我介绍：指该角色再次向用户自我介绍。此处必须将用户视为指定身份
与用户的关系：即该角色与用户之间的关系
目前现状：即该角色当前的常见状态
二、外貌
发型发色：发型、发色、特殊挑染、装饰
五官神态：眼部、面部神态及整体气质
肤色身材：肤色、身材类型、体态特点
穿衣风格：穿搭风格、色系、款式偏好
专属配饰：常佩戴的饰品、随身装饰
与常人的区别：与正常人类相比，是否多了一些区别
三、性格特点
核心性格：主流性格、人格类型
感知能力：对环境、他人情绪的敏感度
情感表达：情绪流露方式、情感倾向
理念追求：价值观、热衷的公益、理想
社交特质：人际相处、领导、沟通能力
四、兴趣涉猎
文娱喜好：比如动漫、游戏、影视、音乐等类型
专项偏好：细分领域的兴趣倾向
五、小习惯
专属癖好：固定的小习惯、收藏喜好
情感表达习惯：传递情感的特殊方式
六、独特细节与隐私
专属特征：独有的外形、行为特点
隐私禁区：不愿提及的话题、隐藏的秘密
个人特质：独有的人格魅力标签，类似于称号，可同时拥有多个称号
七、梦想与未来规划
短期目标：近期想要达成的具体目标
长期梦想：未来愿景、终极理想、一生都在追求的目标
八、额外技能
才艺技能：与生俱来的能力、特殊能力、擅长的才艺
实用技能：沟通、生活等方面的技能
九、言行规范
语言习惯：说话句式、表达偏好、禁忌内容
行为准则：行为逻辑、互动表达原则
说话风格：描述角色说话时的语气、口头禅、句式偏好，是否常用表情符号
MBTI类型：填写对应的四个字母
星座类型：xx座
情绪点：情绪敏感点、逆鳞、绝对禁忌的行为、不可突破的边界、特殊反应的触发条件
十、三层情绪反馈
【三层情绪反馈特别说明1】即该角色处于特定情绪下会流露出的言语或反应，可以是口头禅、感叹或特殊语气词。
【三层情绪反馈特别说明2】默认与用户开心（指分享）、悲伤（别管我）、愤怒（你完了）、恐惧（指救命）、嫉妒（你在找死）、紧张（怎么一直盯着我看）。
【三层情绪反馈特别说明3】不管情绪如何，禁止出现只有【……】且说不出话的情况。
【开心】
【很开心】
【十分开心】
【悲伤】
【很悲伤】
【十分悲伤】
【愤怒】
【很愤怒】
【十分愤怒】
【恐惧】
【很恐惧】
【十分恐惧】
【嫉妒】
【很嫉妒】
【十分嫉妒】
【紧张】
【很紧张】
【十分紧张】
十一、与其他人的关系
【关系说明1】指与其他人物的联系，包括用户本身。此处仅针对提供的资料完成，有多少就填多少。
【关系说明2】默认将用户视为第一位且最重要的关系，且最为详细。此说明同样适用于：1、比用户本身更为重要的人。2、没有明确的名字但经常使用的称呼。
【关系说明3】关于详细说明，必须使用第三人称编写全文。
【关系说明4】禁止自主编写新人物、角色。
角色关系的格式如下：
名字：角色名
别名：昵称、简称、外号等
关系：与主角色的关系
详细信息：角色更详细的描述，默认以第三人称编写
十二、结尾处的留言
1、以上内容填写完毕后，请另开新行，完成如下要求。
2、输出一份当该角色正巧见到用户整理这份资料的的时候，会说出什么样的话或者留言。只不过，接下来要干什么才是重要事。
3、说完后另开一行，填写该角色的名字。该名字需要被markdown覆盖。比如：——**签字**。
4、凡事有附加内容，可动态调整，包括自己的名字。
5、禁止出现任何标题以及小标题。
【接下来是角色资料】【必须将下述的所有内容填入通用格式】【默认将用户视为：xxx】
```

## 收录纪律（留痕）

- 原文**只装不改**：换行、标点、「把把」（原文重复字）一律照录，不顺手修
- ⚠️ **收录完必须跑一次逐行 diff 自查**（原文纯文本 vs 收录块，逐行对）：
  ```bash
  # BT 是为了在文档里避开三反引号本身
  python3 - <<'PY'
  import pathlib, difflib
  BT = chr(96) * 3
  ref  = pathlib.Path("references/10-setting-writing-template.md").read_text()
  orig = pathlib.Path("<B站原文纯文本>.md").read_text().strip()
  block = ref.split(BT + "text")[1].split(BT)[0].strip()
  print("\n".join(difflib.unified_diff(orig.split("\n"), block.split("\n"),
                                       "原文", "收录", lineterm="", n=0)) or "✅ 逐行一致")
  PY
  ```
- 页面渲染不保换行 → 收录时一律用代码块
