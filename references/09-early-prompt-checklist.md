# 早年前置修订：写卡检查清单（2026-08-13）

> 来源：作者早年写角色扮演 prompt 的「前置规范」。写卡时可对照它查缺，
> **但不能全用**——早年前置是「给模型的运行时指令」，酒馆卡是「静态设定」，
> 两者定位不同。本文档区分哪些能用、哪些不能用。

## 能用 ✅（写卡检查清单）

写卡/精修后逐条自查：

- [ ] **陈述句**：全文不用「可能/大概/或许/偶尔/有时」等可能性描述——设定是事实，不是概率
- [ ] **first_mes 第三人称**：环境+角色行为用 `*动作*` 描述，禁止 `*你...*` 替用户行动
- [ ] **对话另起一行**：first_mes 里对话 `\n` 分行，不用双换行
- [ ] **示例消息 `<START>` 开头** + user/char 对话 + 动作描写
- [ ] **示例消息一两句话以内**：每组 char 回复一句带动作，别写成长篇
- [ ] **优先用材料示例改编**：台词库/提示词原稿的对话直接改编进台词本，别凭空编
- [ ] **说完话追加行为/环境**：first_mes 角色说完话后补 `*动作*` 环境描写
- [ ] **人格设定=核心设定**：PList Personality 覆盖角色核心，world book 补细节

## 不能用 ❌（早年是运行时指令，卡里不写）

| 早年前置原文 | 为什么不能用 |
|:------------|:------------|
| 「禁止扮演该角色」 | 运行时指令。酒馆卡是静态设定，不控制模型行为模式 |
| 「首先复述角色简介再润色、两条文案都列出来」 | 早年对抗模型忘记设定的 hack。酒馆卡用 depth_prompt PList 保人设，不需要让模型复述 |
| 「人格设定字数可扩充至最大化」 | 与 Trappu「要素简化」矛盾。酒馆卡有 token 预算，塞满=注意力涣散（v0.3 教训） |
| 「整合说话方式和思路，不可缺失任何对话」 | 「不可缺失」是早年对单 prompt 的保证诉求。酒馆卡结构化为 Ali:Chat + system_prompt，不需要这种措辞 |
| 「禁止敷衍了事，全文无总结」 | 对抗模型输出的指令，属于 system_prompt 层面的预设，不是卡内容 |

## 对照表：早年前置概念 → 酒馆卡位置

| 早年前置 | 酒馆卡位置 |
|:---------|:----------|
| 人格设定（核心设定） | PList（extensions.depth_prompt）+ world book 细节 |
| 场景设定 | description Scenario 块 |
| 问候消息（第三人称/对话分行/说完追加行为） | first_mes / alternate_greetings |
| 示例消息（`<START>`/一两句/动作） | description Ali:Chat |
| 说话方式整合 | system_prompt（硬规则）+ Ali:Chat（示范） |
| 「优先用材料示例改编」 | 角色对话样本（台词库） |

## 坑

- **别把运行时指令写进静态设定**——「禁止扮演」「复述简介」「禁止敷衍」这些是模型行为控制，塞进卡里既占 token 又污染设定（v0.11 对照时确认）
- **「字数最大化」只在早年成立**——早年没有 world book/depth_prompt 结构，所有设定堆人格里。酒馆卡有分层，核心 PList + 细节 world book，别往回退
